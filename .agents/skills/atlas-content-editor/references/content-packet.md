# Content packet
Keep this outside published lesson data in the run directory. Include:
- Run ID, repository revision, authoring mode, actual topic/subject and exact source paths.
- Source register: ID, title, edition/date/hash, exact locator, availability and whether actually consulted.
- Claim register: stable claim ID, statement/formula, assumptions/units, source IDs/locators, origin and verification (the words of the contract's claims field: origin department_source, external_primary, author_derived, illustrative_assumption or unresolved; verification checked_against_source, independently_derived or unverified), and topic anchor.
- Objectives and prerequisite concepts, preserving the distinction between a useful related topic and a required prerequisite.
- Draft narrative/source artifact and its hash; a proposed placement for examples, diagrams, expandable depth and source line.
- Terminology: canonical existing terms, unresolved proposals and evidence; do not maintain a second dictionary.
- Identity baseline: existing oral/question/glossary keys; proposed additions or intentional migrations.
- Designer request: target learners, objectives, source-backed answers, hard constraints and permitted demo files.
- Findings, missing dependencies, and required integration/review scope.

A source register entry proves only what was read and where. It must not claim primary verification when only an existing web lesson was available. A useful draft may remain unresolved; make that visible in its status.
